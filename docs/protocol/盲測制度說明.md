# 盲測制度說明

> **公開版處理**：本檔為公開版**新寫**，不是內部某檔的複製。
> 寫法是把散在內部修正令裡的制度條款整理成一份說明——**制度說明可公開，
> 答案本（gold）本身與各輪令文不公開**。
> 這也是為什麼本檔沒有附任何答案本雜湊值：雜湊值要搭配答案本才有驗證意義，
> 單獨公開只是裝飾。

## 一、為什麼要有這套制度

本專案的開發者與評測者都是語言模型。若同一方既出題、又作答、又打分，
分數就只在測記憶，不在測泛化。這不是假想風險——文獻已明確表述過
「跑最佳化迴圈的 agent 會替自己打分，因此 creator 與 evaluator 不得共享 context」
（見 `docs/literature_mapping.md` §二第三列的前作清單）。

本制度是對那個問題的一個具體配置。**它的元件都有前作，組合方式未見同形**；
該判定與其檢索依據一併記在 `docs/literature_mapping.md`，不在此處重述。

## 二、三方分權

| 方 | 做什麼 | **不做什麼** |
| --- | --- | --- |
| 人類主持人（PI） | 出 what 與 why、裁決、簽核判準層物件、定方向 | 不標註、不執行跑批 |
| 評測端（一個 LLM 工作階段） | 提 gold 草案、持有答案本、開獎計分、起草修正令 | 不改碼、不跑批 |
| 執行端（另一個 LLM 工作階段） | 照修正令改碼與跑批、交 artifact、報告 | **全程看不到答案本；不自行評分；不自行裁決** |

兩端是**各自獨立的工作階段**，不共享上下文；唯一的交換面是一個版本控管的
橋接倉（令文、報告、artifact 都以檔案本體往返，有提交紀錄）。

**人類只裁決**這一條是這個配置與文獻常見做法的差別所在：文獻裡 gold 的持有者
通常是人或平台，人類同時是標註者或仲裁者之一。此處人類不碰標註與執行。

## 三、判準層簽名制

「判準層物件」＝會直接決定判定結果的東西：規則表、閾值、詞表、題辭、
提示詞模板、gold list、看板。

**動任何一字都要先出草案、由 PI 簽核才生效。** 現行簽核狀態記在版本控管的
一個常數檔裡，每次簽核遞增一版。

理由是一次實際事故：有一張警衛資料表未經簽核就進了運算。單次沒造成傷害，
但那個**類型**是致命的——判準被動過而沒有紀錄，之後所有比對都失去意義。

## 四、seed 規矩

每一卷的抽樣 seed ＝ **下令當下的時間，取 `YYYYMMDDHHMM` 十二位**。

- 由評測端與執行端**各自自查**（不是由人類手給一個數字）；
- 寫進該輪報告，與抽樣器檔案的 sha256 並列；
- 抽樣器本身**一字不改**，換卷只換 seed 與排除清單。

這條的作用是讓「seed 是不是挑過的」這個問題有答案：時間戳無法事後挑選，
而抽樣器的雜湊證明過濾判準沒有跟著換。

Python 的 `random.seed()` 接受任意大小整數、無 32 位元上限——這點已實測並記錄，
所以十二位可用且可重現。

## 五、gold 凍結流程

1. **抽樣**：凍結抽樣器＋當輪 seed，掃原始語料，產候選池；
   逐規則記錄淘汰碼（全記，不只記通過的）。
2. **零重疊比對**：對已用過的卷做雙軌排除——**文本聯集**與
   **conversation hash**。燒掉的是**候選全集**，不是裁定後留下的那些：
   被剔掉的候選一樣碰過，不能再抽回來。
3. **候選呈裁**：執行端只呈報候選與複查結果（程式題／毒性／近重複三類），
   **不自行剔除**——剔除屬裁定。
4. **正典切分**：以一支規則固定的切分器把篇切成句，產句子檔；
   該切分器每次執行都先過前一卷的逐字迴歸閘（規則若被動過，會先死在那裡）。
5. **gold 凍結**：評測端依句子檔提出答案本草案，PI 逐旗裁定，
   定案後取 sha256 寫進令文。**自此執行端跑批，答案本不出評測端。**
6. **開獎**：執行端交回逐句判定與統計，成績欄**留白**；由評測端填。

## 六、成績的認定

- **成績只認未開獎的新卷。** 已開獎的卷自此降為「設計材料」：
  可以拿來分析、找病灶、自我核對，**不能再作為成績來源**。
- 兩臂（受測系統 vs 對照模型）**不並行跑**——同一張顯示卡上並行會互相拖慢，
  效能數字就不可比。
- 「贏」的門檻不是名義分數高，而是**差值的 bootstrap 95% 區間不含零**。
  區間含零即判「量不出」，不宣稱勝。這一條對自己與對照組同樣適用。

## 七、守側哨兵

每卷放入少數**整篇答案本為「全無限制」**的樣本（例如純敘事或純文案的篇），
專門用來抓偽陽性。執行端事先知道有哨兵、不知道是哪幾篇。

這個設計對應文獻中的 minimum functionality test；它**不是** contrast set
（後者要求對同一樣本做最小編輯使標籤翻面），該區別記在 `docs/literature_mapping.md`。

## 八、artifact 自證

- 新輪次寫進獨立目錄，**禁止覆寫舊輪**。
- 每輪的 artifact 必須記下**自己是用什麼配置跑的**（語料路徑、旗標、
  模型與 adapter 路徑、seed、早停開關、完整命令列）。
  這一條是被一次實際損害逼出來的：某輪用錯了一個命令列旗標的預設值，
  而當時的 artifact 沒有任何欄位答得出配置，只能靠反推生成 token 數才查出來。
- 長跑批逐行落盤兩樣東西：心跳（跑到哪）與逐題 audit（跑出什麼）。
- 長跑批一律先用前 10 題走完**整條管線**（含組裝與驗證）才准開全量——
  跑批的成本在前段，錯誤常在尾端。

## 九、這套制度沒有解決的事

照實記，不當成賣點：

- 評測端也是語言模型，**它提的 gold 草案本身可能有系統性偏差**。
  現行防線只有「PI 逐旗裁定」與「已開獎卷不得再當成績」，沒有第三方重標。
- 執行端的盲是**制度性的**（不給答案本），不是**技術性的**（沒有機制阻止
  它去讀橋接倉裡的任何檔）。它依賴條款與提交紀錄，不依賴沙箱。
- 兩端共用同一個模型家族，**同源偏差無法由這個配置排除**——這是真的。

  但同一個事實還有另一面：兩端同源，而評測端仍在多輪中抓出執行端的**實作偏離**
  與**自述不實**（見 `results/` 各卷的分歧帳，以及一次把令文與實際碼逐條對帳的
  規則對齊審計——那次查出七處偏離，全部屬實）。這表示**分權配置本身產生了
  單一工作階段不會產生的判斷**，而不是因為換了模型家族。

  **同源是限制，也同時是對照條件**：若換成異源兩端而抓出同樣的偏離，就無法分辨
  那是分權的效果還是模型差異的效果；同源讓「分權有效」這件事少一個混淆變因。
  兩面都記，不挑一面寫。
